Four projects. Four different jobs.

These repositories explore complementary layers of governed campaign operations. They are independent projects, not a single integrated product.

01 / DECISION ENGINE

Governance OS

Use when you want to evaluate synthetic campaign inputs against configurable deterministic pre-flight policy, see findings and portfolio risk, record human review, and inspect local audit evidence.

Documented: Python, JSON policy, Streamlit, synthetic examples and tests.

02 / NARROW POLICY CHECKPOINT

ACC Agent Gate

Use when you want to examine a focused approval checkpoint concept for agent-assisted campaign operations. Review that repository's README for its current implementation scope and deployment status.

Repository ↗

03 / HANDOFF BOUNDARY

Handoff Gate

Use to check a planning package before campaign activation with named deterministic controls, GO / HOLD / BLOCK outcomes, missing-evidence handling, and a SHA-256 fingerprint tied to package and policy version.

Documented: browser, Node.js and CI usage design; interactive demo uses synthetic fictional data.

Repository ↗ · Demo ↗

04 / LOCAL OPERATING WORKBENCH

OPSFORGE

Use to explore a local workflow environment with defined agents, rule-driven tasks, human approval pauses, override reasons and a run ledger / audit trail.

Documented boundary: local MVP; deterministic template provider; no production Campaign connection or authentication.

How the concepts fit

PrepareAgent or operator assembles a package
CheckPolicy gate evaluates named evidence
ReviewHuman records a decision and rationale
TraceEvidence and events remain inspectable

Governance OS emphasizes campaign-level QA and portfolio view. Handoff Gate focuses on the boundary between planning and activation. ACC Agent Gate is a narrower gate concept. OPSFORGE explores a local operating workbench around agent tasks and review. Their repositories do not document a shared runtime or integration between them.
