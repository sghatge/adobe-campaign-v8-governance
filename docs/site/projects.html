01 · Governance engineering

Deterministic controls with accountable review

Policy checks own the decision; advisory assistance can explain evidence but cannot override a mandatory block.

CAMPAIGN QUALITY · PYTHON · STREAMLIT

Governance OS

Independent reference implementation for campaign pre-flight QA. The README documents a Python validation engine, configurable policy, synthetic campaign examples, machine-readable evidence reports and a Streamlit interface. Mandatory FAIL or UNKNOWN results block; warnings remain advisory. The separate investigation layer is read-only.

Evidence: public source documents consent and suppression checks, workflow readiness, typology and proof approval, asynchronous delivery status, and downloadable JSON evidence. The repository includes an automated test suite and GitHub Actions workflows; no test count is claimed here.

Boundary: synthetic examples only; no production Campaign connection, campaign execution, AI override or uploaded-file persistence. Independent project, not affiliated with Adobe.

MARKETING WORKFLOW · PYTHON · STREAMLIT

Digital Marketing AI Agents

A lightweight workflow prototype that turns a brief into strategy, editable content drafts, campaign QA checks and transparent performance calculations. Four task-focused agents cover campaign strategy, content, QA and performance analysis.

Evidence: source README documents URL-format and UTM completeness checks, content presence and absolute-claim phrase checks, plus arithmetic for delivery, CTR, conversion and cost per conversion. Optional Gemini-assisted copy is available when configured server-side.

Boundary: no live ad, email, CRM or analytics connections; URL checks do not visit links, and copy checks are not legal or privacy approval. Synthetic or sanitized inputs and human review are required.

02 · CRM operations and agent governance

Reusable workflows, bounded by evidence and people

REUSABLE AGENT SKILLS

CRM Ops AI Skills

A collection of task-specific skills for campaign QA, troubleshooting, performance reporting, lifecycle tracking, postmortems and capacity planning. The documented operating pattern classifies claims as FACT, HYPOTHESIS, ASSUMPTION or UNKNOWN and traces findings to source evidence; a human reviews and sends outputs.

Documented stack: Claude Agent Skills and reusable workflow instructions; outputs include verdicts, reports, workbooks and draft communications. The repository includes installation guidance and a worked showcase.

Evidence note: time-saved numbers in the repository are explicitly estimates for a stated scenario, not measured outcomes; this showcase makes no productivity claim.

LOCAL CRM WORKBENCH · PYTHON · STREAMLIT

CRM AI Agent Platform

A platform-agnostic local workbench with eight guided CRM operations workflows, structured draft outputs, evidence-first templates and basic deterministic checks for campaign QA, KPI data and workload capacity.

Evidence: repository README identifies the eight workflows and provides local run instructions.

Boundary: current starter version does not call a live LLM or CRM API, authenticate, send messages or deploy campaigns. No production integration is documented.

LOCAL GOVERNED OPERATIONS PLATFORM · PYTHON

OPSFORGE

A local MVP with defined agent plans and tools, rule-driven campaign QA, audience validation, release-readiness checks, human approval pauses, written reasons for overrides, and a persisted run ledger and audit trail. README walkthroughs describe synthetic demo data and local startup.

Documented components: five registered agents, mock CRM and dry-run Adobe Campaign interface stubs, process register, ROI calculator, evidence register and audit. The README reports an automated test suite; this page does not repeat a count.

Boundary: deterministic template provider, no external LLM calls by default; no production Campaign connectivity, authentication or multi-user roles. Local MVP, not production deployment.

DETERMINISTIC HANDOFF GATE · BROWSER / NODE.JS / CI

Handoff Gate

A policy-based checkpoint between AI planning and campaign activation with GO, HOLD or BLOCK outcomes. Named checks and missing evidence fail closed; HOLD identifies the person who can clear it; a SHA-256 fingerprint ties the verdict to the evaluated package and policy version.

Available: project homepage, interactive demo and six-slide carousel are linked from the repository README.

Boundary: synthetic demonstration data (fictional Lumen & Loom); no Adobe affiliation.

BROWSER-ONLY ASSESSMENT · HTML / JAVASCRIPT

AI Readiness Calculator

A browser-based self-assessment with 31 questions across 10 dimensions, a weighted readiness score, governance cap for a data-handling risk flag, action planning, scenario comparison, history, workshop views and reports.

Evidence: scoring model and dimension weights are documented in README; history and workshop information are stored in browser local storage, and the README states answers are not sent to a server.

Boundary: the repository describes fictional sample employees and an assessment conversation starter, not an employment diagnosis. Follow its privacy guidance before using real responses.
